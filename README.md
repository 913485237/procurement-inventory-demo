# 采购与库存补货协同管理系统

面向采购专员和供应链岗位的独立个人项目。系统围绕“库存风险识别 → 补货决策 → 采购审批 → 采购单 → 到货与订单影响跟踪”构建采购业务闭环。

本项目使用虚构业务数据，提供本地可复现运行方式和 Docker 启动方式，用于展示采购流程梳理、供应商与订单关系设计、权限控制和业务系统落地能力。

本仓库以**本地运行**为主，不需要 GitHub、Render 或其他云端服务。启动后请在本机浏览器访问 [http://127.0.0.1:8765](http://127.0.0.1:8765)。

> `render.yaml` 仅保留为可选的部署配置；它不会自动创建在线地址。若未自行部署，请不要点击或依赖外网部署链接。

## 核心流程

```text
库存不足或订单需求增加
        ↓
识别补货风险
        ↓
生成 AI 或人工补货建议
        ↓
采购人员确认数量、供应商和到货时间
        ↓
提交采购审批
        ↓
生成采购单
        ↓
跟踪到货及订单交付影响
```

## 核心功能

- 物料库存、安全库存和订单需求分析；
- 供应商信息、交期和采购历史查看；
- AI 补货建议与采购人员人工经验判断；
- 采购申请、审批、驳回、复核和采购单生成；
- 到货时间、采购状态和受影响订单跟踪；
- 采购、仓库、销售、财务和管理员角色权限；
- 通知抽屉、业务详情、审计记录和演示数据重置；
- 外部 AI → 本地 Ollama → 本地规则引擎降级链。

## 快速体验

### Windows 本地启动

双击运行 [启动AI-ERP.bat](启动AI-ERP.bat)，或在项目目录执行：

```powershell
python app.py --open
```

看到“`Aether AI ERP 已启动`”后，在本机浏览器打开 `http://127.0.0.1:8765`。随后切换到“周岚 · 采购经理”，进入“供应链风险”，打开航空铝板缺口，执行人工补货或 AI 补货建议。

### Docker 启动

项目不依赖第三方 Python 或前端包，可以直接构建并启动：

```powershell
docker build -t procurement-demo .
docker run --rm -p 8765:8765 procurement-demo
```

Docker 镜像默认开启 `PUBLIC_DEMO=true`：访客可以切换虚构角色并完成采购审批，但不能修改 AI 配置或重置共享数据。若只在可信本地环境使用，可通过 `-e PUBLIC_DEMO=false` 恢复完整管理功能。

云平台若自动注入 `PORT` 环境变量，容器会读取该端口启动服务。

### 可选云端部署

仓库根目录的 `render.yaml` 提供 Docker Web Service、`/api/health` 健康检查和公开演示环境变量配置。只有在自行创建并完成云端部署后，才会获得独立的在线演示地址；本地使用不受影响。

## AI 降级策略

系统按以下顺序选择能力：

1. 外部 OpenAI 兼容接口；
2. 本地 Ollama；
3. 内置规则引擎。

没有外部接口或本地模型时，规则引擎仍支持风险分析、补货方案和权限说明等演示指令。AI 只提供辅助建议，高风险采购动作必须经过人工审批。

## 项目边界

这是一个独立设计的个人项目，不代表已经服务真实企业客户，也不使用真实经营数据。项目重点是展示采购业务流程和业务系统实现能力，不宣称为完整企业级 ERP 或生产环境权限系统。

## 简历写法

> 独立设计并开发面向中小企业采购场景的供应链业务管理系统，围绕库存预警、补货决策、供应商选择、采购审批、采购单生成和到货跟踪，构建从库存异常发现到采购执行的完整业务闭环。项目提供 GitHub 源码、本地可复现运行和 Docker 启动方式，使用虚构业务数据模拟采购人员的实际工作流程。
