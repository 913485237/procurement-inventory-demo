# 项目清理与双版本打包设计

## 目标

将现有采购与库存补货协同管理系统整理为结构清晰、可继续开发的源码项目，并同时生成适合交付的源码版压缩包和适合直接体验的运行版压缩包。

## 清理边界

### 删除

- 所有 `__pycache__/` 目录和 `*.pyc` 文件；
- `data/` 下自动生成的 SQLite 数据库及其临时文件；
- 已完成任务后不再需要的根目录过程记录：`task_plan.md`、`findings.md`、`progress.md`；
- 其他经检查确认可自动生成且未被源码引用的临时文件。

### 保留但不打包

- 本地 `.git/` 目录保留，以免破坏版本历史和 GitHub 远程关联；
- `.git/` 不进入任何压缩包；
- 最终生成的 `dist/` 不反向进入源码版压缩包。

## 目录整理

- `docs/guides/`：采购岗位演示脚本和客户演示脚本；
- `docs/design/`：业务功能、界面交互和交付方案设计文档；
- `docs/implementation/`：实现计划类文档；
- `backend/`、`web/`、`tests/`、`scripts/` 保持既有职责；
- 根目录仅保留项目入口、README、配置示例、启动文件及部署配置。

移动文档后必须同步修正 README 中的链接，并使用全文搜索确认不存在旧路径引用。

## 源码版压缩包

文件名：`dist/采购库存补货协同系统-源码版.zip`

包含：

- Python 服务端与浏览器前端源码；
- 自动化测试和测试脚本；
- Docker、Render、配置示例与本地启动脚本；
- README、使用指南、设计文档和实现计划；
- 空的 `data/` 目录标记或由程序首次启动自动创建目录。

排除：

- `.git/`、`dist/`、缓存、日志、SQLite 数据库、密钥和本地私有配置。

## 运行版压缩包

文件名：`dist/采购库存补货协同系统-运行版.zip`

包含：

- `app.py`、`backend/`、`web/`；
- `config.example.json`；
- Windows 启动脚本和 `scripts/start.ps1`；
- 一份面向体验者的精简运行说明。

排除：

- `.git/`、测试、设计文档、部署配置、过程记录、缓存和数据库。

运行版解压后执行启动脚本即可启动，数据库由应用首次运行自动初始化。

## 验收顺序

1. 删除前生成准确清单并校验目标均位于 `C:\网页\频转` 内；
2. 先运行 Python 语法检查和快速冒烟测试；
3. 整理目录、同步链接并清除可再生文件；
4. 运行 19 项单元测试和完整业务冒烟测试；
5. 生成两个 ZIP，并列出压缩包清单确认无 `.git`、数据库、缓存和私有配置；
6. 将两个 ZIP 分别解压到独立临时验收目录；
7. 源码版运行快速测试，运行版实际启动并检查 `/api/health`；
8. 计算压缩包 SHA-256，记录文件大小和验证结果。

## 安全与回滚

- 删除操作仅针对经解析后的项目内明确路径，不使用未验证的递归通配删除；
- Git 已跟踪文件的移动和删除可通过版本历史恢复；
- `.git/`、核心源码和用户配置不作为删除目标；
- 如果任一测试失败，停止打包并先修复或恢复对应变更。
