# AI 原生制造业 ERP 演示系统设计

## 1. 项目目标

在本地构建一套面向客户和管理层演示的制造业 AI ERP 系统。系统复现参考视频的核心逻辑：AI 不只是聊天助手，而是继承用户权限、能够读取业务数据、规划操作、发起审批并执行 ERP 动作的“数字员工”。

演示必须在无网络、无外部 AI 接口、未安装本地模型时仍可完整运行；配置外部 OpenAI 兼容接口或本地 Ollama 后，可自动获得更自由的自然语言交互能力。

## 2. 范围与成功标准

### 2.1 核心范围

- 制造业经营总览
- AI 指挥中心
- 供应链风险追溯
- 采购、库存、订单、供应商、出货和发票工作台
- 高风险操作审批
- 权限校验与审计日志
- 外部 AI、Ollama、规则引擎三级降级
- 一键启动和演示数据重置

### 2.2 成功标准

- 无网络和无 AI 服务时，可完成“发现缺料风险—分析影响—生成方案—人工审批—执行调整—出货开票—查看审计”的完整主线。
- 配置外部接口或 Ollama 后，不修改业务代码即可切换自然语言能力。
- AI 与当前用户使用同一套角色权限，禁止绕过服务端业务接口直接访问数据库。
- 高风险操作必须审批，关键操作必须有完整审计记录。
- 业务事务失败时完整回滚，重复请求不造成重复出货或重复开票。
- Windows 环境可通过一个启动脚本运行，并附中文说明。

## 3. 技术架构

采用零第三方运行时依赖的本地全栈方案：

- 前端：原生 HTML、CSS、JavaScript。
- 后端：Python 标准库 HTTP 服务。
- 数据库：SQLite。
- AI 适配：Python 标准库 HTTP 客户端，统一对接 OpenAI 兼容接口、Ollama 和规则引擎。
- 启动：Windows PowerShell 启动脚本；启动后输出并可访问本地 URL。

### 3.1 模块边界

- `server`：HTTP 路由、静态资源和统一错误响应。
- `database`：SQLite 初始化、查询、事务和演示数据重置。
- `auth`：用户、角色、权限与 AI 权限继承。
- `erp`：采购、库存、销售订单、出货和发票领域服务。
- `risk`：缺料检测、影响链计算和处理建议。
- `approval`：中高风险动作的草稿、审批和执行。
- `ai`：意图解析、计划生成、提供方降级和规则引擎。
- `audit`：指令、权限判断、审批、API 调用和数据变更记录。
- `web`：页面、组件、样式、状态管理与 API 客户端。

每个模块只通过明确的函数或 HTTP 接口交互。AI 模块只能调用已登记的业务动作，不直接拼接 SQL。

## 4. 页面与演示动线

### 4.1 经营总览

浅色 ERP 仪表盘，展示订单额、库存预警、待审批、待出货、待开票和供应链风险。提供当前角色切换和演示主线入口。

### 4.2 AI 指挥中心

深色科技界面，包含：

- 自然语言输入与建议指令
- 当前用户、角色和继承权限
- AI 服务状态与实际降级路径
- 结构化执行计划
- 每一步的权限、风险和执行状态
- 供应链影响图与审批跳转

### 4.3 供应链风险中心

以原材料短缺为起点，展示供应商、采购单、生产任务、销售订单和关键客户的影响链。支持查看受影响数量、交付日期、风险等级和建议动作。

### 4.4 业务工作台

用标签或左侧导航组织供应商、采购、库存、销售订单、出货和发票。列表支持搜索、筛选、查看详情和授权操作。

### 4.5 审批中心

展示 AI 或人工发起的中高风险动作，包括变更前后数据、影响范围、申请原因和执行计划。审批人可批准、驳回并填写意见。

### 4.6 审计与设置

审计页面按时间线展示 AI 指令、权限判断、提供方调用、审批和业务变更。设置页面配置外部 OpenAI 兼容接口、Ollama 地址、模型名称、超时和降级策略；密钥不返回到前端展示。

### 4.7 客户演示主线

1. 经营总览发现原材料缺料预警。
2. 进入 AI 指挥中心，让 AI 分析受影响订单和关键客户。
3. AI 生成补货、订单调整和交付协调方案。
4. 高风险动作进入审批中心。
5. 管理员批准，AI 在事务中执行补货或订单调整。
6. 仓库角色确认出货，财务角色确认开票。
7. 审计页面展示从指令到数据变更的完整链路。

## 5. 业务模型

### 5.1 主要实体

- 用户、角色、权限
- 供应商、原材料、库存批次
- 采购单、采购明细
- 客户、销售订单、订单明细
- 生产任务
- 出货单、发票
- 风险事件、影响关系
- AI 会话、AI 计划、计划步骤
- 审批单、审批记录
- 审计日志、幂等记录

### 5.2 预置角色

- 管理员：全部权限和系统配置。
- 采购经理：供应商、采购单和补货。
- 仓库主管：库存、入库和出货。
- 销售经理：客户、销售订单和交付协调。
- 财务专员：发票、回款与财务确认。

本地演示通过角色切换模拟多用户协作，不实现真实密码登录；页面始终明确显示当前角色，避免误解。

## 6. AI 计划与权限机制

### 6.1 提供方降级

按以下顺序尝试：

1. 已配置且可用的 OpenAI 兼容接口。
2. 已配置或可探测的本地 Ollama。
3. 内置规则引擎。

每次切换都记录原因、耗时和最终提供方。外部服务超时不阻塞演示，降级总时长受统一超时限制。

### 6.2 结构化计划

AI 输出必须转换为服务端定义的结构化计划，至少包含：

- 意图
- 业务动作标识
- 参数
- 数据依据
- 风险级别
- 所需权限
- 是否需要审批

服务端不执行模型生成的任意代码、SQL 或未知工具名。所有动作必须来自受控动作注册表。

### 6.3 风险分级

- 低风险：查询库存、订单、供应商和风险数据，可直接执行。
- 中风险：生成补货单、调整建议和出货草稿，只保存草稿或进入简化确认。
- 高风险：批量采购、修改正式订单、确认出货、开具发票，必须人工审批。

### 6.4 执行流程

`用户指令 → 生成结构化计划 → 校验动作与参数 → 继承用户权限 → 查询业务数据 → 计算风险 → 自动执行或创建审批 → SQLite 事务提交 → 写入审计记录`

## 7. 供应链风险场景

预置一个原材料短缺事件。系统根据 BOM/订单用料、可用库存、未到货采购单和交付日期，计算：

- 缺口数量
- 关联供应商和采购单
- 受影响生产任务
- 受影响销售订单
- 关键客户和紧急订单
- 建议补货、替代料或交付协调动作

影响链必须可解释，页面显示数据来源和计算过程，避免只给出黑盒结论。

## 8. 视觉设计

- 浅色业务区：白色卡片、浅灰背景、深蓝文字、青蓝主色，体现企业系统的清晰可信。
- 深色 AI 区：深海军蓝背景、青色高光、流动节点和执行状态，体现 AI 指挥能力。
- 状态色：绿色表示已执行，黄色表示待审批，红色表示高风险，灰色表示未开始。
- 优先适配 1920×1080 和常见笔记本宽屏；小屏允许表格横向滚动。
- 所有页面使用真实感中文制造业示例数据，不出现无意义占位文案。
- 动效只用于风险链、执行步骤和状态切换，避免影响商务可信度。

## 9. 异常处理与安全边界

- 外部 AI 或 Ollama 超时后自动降级，页面显示降级原因。
- 权限不足返回动作、当前角色和所需权限，不泄露受限业务数据。
- SQLite 写操作使用事务，任一步失败则整体回滚。
- 出货、开票和审批执行使用幂等键，重复请求返回原结果。
- AI 不得直接访问数据库，不得执行任意代码，不得调用动作注册表之外的操作。
- 配置密钥只保存在本地配置文件中，日志和 API 响应必须脱敏。
- 重置演示数据必须明确确认，只重建演示数据库，不触碰视频和项目源码。

## 10. 测试与验证

使用 Python 标准库 `unittest` 覆盖：

- 各角色允许和拒绝的动作
- AI 权限继承
- 外部接口失败后降级到 Ollama 和规则引擎
- 缺料风险与影响订单计算
- 高风险动作创建审批
- 审批后事务执行与审计写入
- 事务失败回滚
- 重复出货和重复开票的幂等保护
- 演示数据重置

另提供 API 冒烟测试，验证服务启动、静态页面、核心查询、AI 指令、审批和审计端点。前端进行桌面宽屏、笔记本宽屏以及离线模式的人工验收。

- SQLite 初始化结构和演示数据
- Windows 一键启动脚本
- 中文 README、配置说明和五分钟演示脚本
- 自动化测试与测试运行脚本

## 12. 非目标

- 不实现生产级账号密码、单点登录或公网部署。
- 不接入真实企业 ERP、支付、税控或物流系统。
- 不让 AI 绕过审批自动执行财务或法律意义上的真实操作。
- 不使用模型生成的任意代码或 SQL。
- 不承诺规则引擎理解演示主线之外的任意自然语言。
