# 订单详情弹窗设计

## 背景

业务工作台的销售订单目前以静态表格展示。订单号、客户及整行都没有点击反馈，用户无法从列表继续查看订单的产品、生产、履约和风险信息。

## 目标

- 销售订单整行可以点击，并提供明确的悬停与键盘焦点反馈。
- 点击订单号、客户名称或整行后打开居中的订单详情弹窗。
- 详情数据从后端按订单 ID 实时读取，覆盖订单、客户、产品物料、生产、出货、发票和风险关联。
- 弹窗适配浅色与深色主题，并在小屏幕下使用接近全屏的纵向布局。

## 交互

- 仅销售订单列表启用详情交互，其他业务页签保持原有行为。
- 每一行使用可聚焦的交互语义，支持鼠标点击、`Enter` 和空格键打开。
- 打开后先显示加载状态，接口成功后渲染详情；失败时在弹窗内显示错误和关闭入口。
- 点击关闭按钮、底部“关闭”、遮罩空白处或按 `Escape` 关闭弹窗。
- 重复点击不同订单时按新订单 ID 重新读取，避免沿用旧订单详情。

## 详情结构

1. 顶部摘要：订单号、状态、优先级、订单金额。
2. 订单信息：创建时间、交付日期和交付倒计时。
3. 客户信息：客户编码、名称、等级、行业和联系人。
4. 产品与物料：产品名称、数量、物料编码、物料名称、规格、单位用量和需求总量。
5. 生产进度：工单号、任务状态、已完成量、需求量和完成率。
6. 履约信息：关联出货单和发票；没有记录时显示明确的空状态。
7. 风险关联：列出该订单当前生产任务关联物料的未关闭风险事件；没有风险时显示“暂无关联风险”。

## 后端接口

- 新增只读接口 `GET /api/orders/{id}`。
- 复用 `order.read` 权限校验，角色无权时返回现有权限错误。
- 订单不存在时返回业务错误，不返回空壳详情。
- 接口聚合多个只读查询，不修改数据库和审计记录。

## 视觉与响应式

- 复用现有遮罩和弹窗基础样式，详情弹窗桌面宽度扩大到约 900px。
- 摘要区与信息卡保持当前业务系统的圆角、边框和颜色体系。
- 订单号和客户名称呈现链接式强调，整行悬停出现浅色高亮和轻微边框强调。
- 深色模式下所有弹窗背景、卡片、文字、标签与进度条随主题变量统一变化。
- 小于 800px 时弹窗占用大部分视口，双栏改为单栏，表格区域允许横向滚动。

## 异常与状态

- 加载期间禁用重复内容渲染并显示加载提示。
- 请求失败时保留弹窗，展示错误原因，避免页面无反馈。
- 没有出货、发票或风险记录时显示独立空状态，不误报为接口失败。
- 详情弹窗与审批弹窗分别维护状态，关闭一个不会误改另一个的业务数据。

## 验收标准

1. 点击订单号、客户名称和行内空白区域均能打开对应订单详情。
2. 键盘聚焦订单行后按 `Enter` 或空格可打开详情。
3. SO-202608-0226 能显示控制柜 C2、生产工单、待承运出货单及无发票状态。
4. 其他订单能显示各自产品、生产进度和关联物料风险。
5. 关闭按钮、底部按钮、遮罩与 `Escape` 均可关闭弹窗。
6. 浅色、深色和移动端布局均无文字错位或内容溢出。
7. 权限校验、现有业务页签、审批弹窗和后端测试继续正常工作。
