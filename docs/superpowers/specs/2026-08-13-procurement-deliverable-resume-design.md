# 采购与库存补货协同管理系统：可交付版本与简历定位设计

## 1. 项目定位

本项目定位为“采购与库存补货协同管理系统”，是一个独立设计与开发的个人项目，面向中小企业采购场景，用于展示采购业务流程理解和业务系统落地能力。

项目不宣称为完整企业级 ERP，也不虚构真实企业客户、经营数据或效率提升比例。所有演示数据均使用虚构数据。

## 2. 核心业务闭环

项目只围绕一条采购主线展开：

```text
库存不足或订单需求增加
        ↓
识别补货风险
        ↓
生成 AI 或人工补货建议
        ↓
采购人员确认数量、供应商和到货时间
        ↓
提交采购审批
        ↓
生成采购单
        ↓
跟踪到货及订单交付影响
```

保留的支撑模块包括物料库存、供应商信息、采购申请与采购单、采购审批、订单交付风险、通知提醒、操作记录和采购岗位权限。

暂不以完整财务 ERP、真实企业接口、多租户 SaaS、复杂 AI 模型训练或真实企业经营数据为项目目标。

## 3. 采购岗位演示路径

线上演示不要求访客注册，默认提供采购专员演示入口。

推荐路径：

```text
进入采购演示
  ↓
查看待补货物料
  ↓
打开高风险库存记录
  ↓
查看缺口和受影响订单
  ↓
选择人工补货方案或查看 AI 建议
  ↓
提交采购审批
  ↓
查看审批详情
  ↓
查看生成的采购单
  ↓
查看到货时间和订单影响
```

采购岗位首页重点展示待处理补货任务、高风险缺货物料、待审批采购申请、预计影响订单、供应商交付风险和采购订单数量。

## 4. 关键业务能力

### 4.1 库存风险识别

展示物料名称、当前库存、安全库存、近期需求、缺口数量、风险等级、受影响订单和建议到货时间。

### 4.2 补货决策

支持 AI 建议和人工判断两种方式。人工方案必须能够记录补货数量、供应商、预计到货时间、紧急程度、补货原因、订单交付影响和备注。

### 4.3 采购审批

审批详情展示物料、数量、供应商、预计金额、到货时间、风险等级、关联订单、补货依据及建议来源，并支持通过、驳回和要求修改。

### 4.4 采购执行与跟踪

审批通过后生成采购单，展示采购单号、供应商、物料、数量、金额、下单时间、预计到货时间、状态、关联订单和交付风险。

### 4.5 权限与留痕

按采购、仓库、销售和管理者角色限制可执行操作，并记录关键审批和业务操作。

## 5. 交付形式

采用“GitHub 仓库 + 在线演示地址 + README + 简短演示视频”的组合。

### 5.1 GitHub 仓库

README 第一屏应说明项目名称、业务问题、在线演示地址、演示账号、核心流程、截图、架构、本地运行方式、测试方式以及项目边界。

仓库结构建议保持职责清晰：

```text
backend/       业务接口、权限、风险判断、采购流程
web/           页面和交互
data/          演示数据或初始化脚本
tests/         权限、补货、审批和回滚测试
docs/          业务流程、架构说明和演示脚本
scripts/       启动、初始化和测试脚本
README.md      项目说明
```

### 5.2 线上环境

线上演示使用虚构数据，支持初始化和恢复演示数据；刷新页面后关键数据保持一致；无外部 AI 接口时由本地规则引擎维持核心流程可用；不暴露 API 密钥；所有关键操作均提供成功或失败反馈。

### 5.3 交付验收标准

- HR 在 3 分钟内理解项目解决的问题；
- HR 在 5 分钟内完成一次补货采购流程；
- README 能说明业务背景、角色、流程和运行方式；
- 项目明确标注为独立设计的个人项目；
- 演示数据全部为虚构数据；
- 支持线上体验和本地运行。

## 6. 简历定位

项目标题：

> 采购与库存补货协同管理系统｜个人项目

项目描述：

> 独立设计并开发面向中小企业采购场景的供应链业务管理系统，围绕库存预警、补货决策、供应商选择、采购审批、采购单生成和到货跟踪，构建从库存异常发现到采购执行的完整业务闭环。项目提供线上演示环境和 GitHub 源码，使用虚构业务数据模拟采购人员的实际工作流程。

推荐关键词：

`采购申请`、`补货计划`、`库存预警`、`供应商管理`、`采购订单`、`到货时间`、`采购审批`、`交付风险`、`跨部门协同`、`操作留痕`。

简历表述必须使用“独立设计并开发”“模拟采购流程”“提供线上演示”等真实措辞，不使用未经证明的企业客户、成本节省或效率提升数据。

## 7. 面试口径

面试时将项目解释为：一个独立设计的个人项目，目标是减少采购人员在库存、订单和供应商信息之间反复确认的成本。系统根据库存、安全库存和订单需求识别补货风险，再由采购人员确认供应商、数量和到货时间，提交审批后生成采购单，并跟踪到货及其对订单交付的影响。AI 只提供辅助建议，最终决策由业务人员负责。
